# CLAUDE.md

Personal Android reminder app (Kotlin, Jetpack Compose, Material 3) with place reminders through geofencing. Sibling of `another-habit-tracker`, which is the reference for design and build conventions: read its `CLAUDE.md` when in doubt.

## Rules

- **This repository is public.** Never commit signing material, data exports, or anything that places the owner: no real coordinates, addresses or shops of home, work or the neighbourhood, in code, tests, comments or screenshots. Examples use central Milan (Viale Piave 38, Via Dante, the Duomo).
- Never change `applicationId` (`dev.eduarddragu.anotherreminderapp`) or the signing setup: either one breaks in-place updates and loses data on the phone.
- Don't commit or push unless explicitly asked.
- Code, comments, docs and UI strings in English. Plain prose, no em dashes.
- `INTERNET` is used only by `data/MapsLinks` (expanding a shared Maps short link, Google hosts only) and `data/Tiles` (OpenStreetMap tiles for `SpotMap`, under OSM's tile policy: identifying User-Agent, two connections at most, 30-day disk cache in `cacheDir/tiles`, "Maps © OpenStreetMap contributors" wherever tiles show). The place search (`data/Search`) uses OpenStreetMap's Nominatim (Android's `Geocoder` only knows addresses, not shops), biased to about 25 km around the last known position, one request a second per its policy; a query that finds nothing is retried as name plus area ("esselunga lorenteggio": Lorenteggio first, then Esselunga within about 6 km of it). A Maps link, shared or pasted in the search field, is expanded (`MapsLinks.resolve`): coordinates when a hop has them, else the name and address of its `/maps/place/` path (what phone share links expand to now), searched whole and then as the address alone (`MapsShare.searches`), with the results listed to pick from. Nothing else goes on the network: no analytics, no crash reporting. `data.json` is excluded from the Google account backup (spots can be home or work) and moves only with a device transfer.
- Use the `android` CLI (with `--no-metrics`) and `android docs search` for current API guidance.

## Layout

- `domain/`: pure Kotlin, unit tested (`DomainTest`). `Data` (places and reminders, one serializable document; ids are shared and a reminder's id is also its notification id and alarm request code), `Fences.plan` (one geofence per spot of every place with a reminder, capped at 100, request id `<placeId>:<index>`), `Coordinates` (pasted coordinates or a maps URL; a place URL's `!3d<lat>!4d<lng>` wins over its `@` map centre), `MapsShare` (what Google Maps' Share sends: name, address, spot, link), `Spot.label` (what a spot is, "Esselunga · Viale Piave 38"; never part of a fence), `Repeat` (every N days/weeks/months/years), `Data.complete` and `nextRepeat` (Done on a repeating reminder moves it to the first step after now, at least one on, counted from its first date in local time), `Copy` (notification titles from small pools, picked by reminder id plus day: repeating reminders get their own lines; date labels; Home's line), `Countdown`, `Nudges` (every notification of a time reminder: a heads-up a week before at 10:00 and the evening before at 20:00, the reminder itself, then while not done nudges at +1, 2, 4, 8, 16 h and once a day for a week, moved out of 22:00 to 08:00; `Reminder.lastNudge` says where the sequence is, gone-by heads-ups and nudges are skipped, the reminder itself never) and `Mercator` (tile maths and the frame that fits a place's spots).
- `data/Store`: the document as `files/data.json` (AtomicFile), loaded in `ReminderApp.onCreate` so receivers can read it; an unreadable file is copied aside before starting empty. `Store.update` saves, then syncs alarms and, when the fence plan changed, geofences.
- `triggers/`: `Alarms` (one exact alarm per time reminder, for its next nudge; the alarm carries the reminder's time it was planned for, so an edit makes it stale), `PlaceWatch` (DWELL only, 2 min loitering, no initial trigger. Replacing a fence restarts its dwell, so `update` touches only the fences whose plan changed, and the full `resync` runs only after boot, an app update, location coming back on, a permission just granted, or a known problem; never just because the app opened. `problem` feeds Home; `needsResync` is a saved flag set when a fence couldn't be added or Play services dropped them (GEOFENCE_NOT_AVAILABLE), cleared only by a full resync that succeeds, and while it's set the hourly check and opening the app resync; `SystemReceiver` holds its broadcast open with `goAsync` until Play services answers), `GeofenceReceiver`, `AlarmReceiver`, `DoneReceiver`, `SystemReceiver` (not exported; boot, app update, time and time zone changes (alarms only: the nudges' hours are local), and an hourly check that resyncs only when location went from off to on: geofences are dropped when location is turned off and `PROVIDERS_CHANGED` doesn't reach manifest receivers), `Notifications` (channel `reminders_v1`, high importance; channel sound can't change after creation, so behaviour changes need a new id; Done from a notification leaves a silent "Done." with Undo for 10 s, carrying the reminder as it was).
- Home's mark is `ui/components/Beacon.kt`, an outline compass (the habit tracker's planet stays the tracker's own): an accent rim with a slow pulse, a sparse rose with an italic N that spins in on arrival and swings gently, and the rim's arc as the countdown to the next time reminder (full when one is due), with the rose faded behind the number. The launcher icon (`res/drawable/ic_launcher_foreground.xml` and `_monochrome.xml`) is the same compass, generated as vector paths; keep the two in step. Notification copy (`domain/Copy.kt`) is warm and grateful, a note from past you; never bossy.
- Place reminders are grouped by place and never go through the reminder editor: `ui/PlaceChecklist.kt` is the one list, on Home's card for the place ("All done" there) and on the place's page ("Things to do here"). Items are DM Sans bodyLarge (the serif stays the voice of a card's one title), a 20dp check circle in the header's 22dp icon column, 10dp to the text, 36dp rows. On Home a tap on the card outside the items (the label, the margins) opens the place's page (chevron on the label row), or, while a field is open, only closes it. Each thing has a round check; a tap anywhere on its line edits it in place (Enter saves, emptied it goes); "Add" opens a line that adds one per Enter. Inline fields close when they lose focus (`Screen` clears focus on a tap on empty space) or the keyboard goes down, keeping what was typed; closing can be reported twice, so what a close does is decided by `domain/Checklist.close` (tested: a second close never removes the item)., and one notification per place (the place's id, which no reminder shares; InboxStyle; "All done"). Done and Undo from notifications carry lists of reminders.
- Places can be reordered: hold a card on the places list, drag it (`PlacesScreen`, `Data.reorderPlaces`); Home lists place reminders in that order.
- `ui/`: four screens on a plain back stack in `App.kt` (Home, reminder editor, places, place editor) with `rememberSaveableStateHolder`; a place created from the reminder editor is selected there on return, and a new place saved straight from Home (a Maps share) stays open as that place's page, where its list is written. Both editors guard Save against a second tap and ask before back throws away changes. The place editor puts "Find it" (search following the name until edited, results that stay after a pick, "Where I am" and "Google Maps") before the place card (map, labelled spots, radius); editing an existing place shows the place card first, with finding another spot folded behind "Add another spot". Spots with no label (pasted coordinates, or from before labels) get their address from Nominatim's reverse lookup once (`Search.label`), kept on a saved place without asking. `MainActivity` is `singleTask` and takes `ACTION_SEND` text: a Maps share goes to the place editor on top, or opens a new one (name prefilled); a short link is expanded there through `MapsLinks`. Home ticks every minute for the countdowns. `MainActivity` tracks notification and location permissions and builds Home's problem cards, and resyncs geofences on resume only when a problem is showing or background location was just granted. The back stack and drafts are saveable (routes as strings), so they survive the process dying while Google Maps is open. Ids are never reused (`Data.nextId`). Components (`Field`, `SectionLabel`, `TextAction`, `CardLabel`, `ScreenTitle`, `Screen`) and `theme/` are copied from the habit tracker: same palette, fonts, radii (12 controls, 24 cards) and motion. Keep them in step with it.

## Build and device

- `scripts/install.sh [release|debug]` builds, installs with `adb install -r` and launches. Release by default (R8; Compose in debug is janky).
- Target device: Pixel 8 Pro, Android 17. `minSdk` 34.
- Bump `versionCode` for every build installed on the phone. A field added to `Data` needs a default value so older files still load (`ignoreUnknownKeys` covers removed ones).
- Never run `connectedAndroidTest` on the phone in use: AGP uninstalls the app afterwards.
- Inspect: `adb shell dumpsys alarm | grep -A3 anotherreminderapp`, `adb shell dumpsys notification --noredact`. Geofences live inside Play services; a failure to register shows on Home and in `adb logcat -s PlaceWatch`.
- README screenshots live in `docs/assets/screenshots/` (540x1111): home, lists (Home scrolled), place, editor, places, each as `<name>.png` and `<name>-dark.png`; the README shows the light ones. They are taken on the phone with demo data, never the owner's: install the debug build (same key, data kept), copy `files/data.json` off the phone with `run-as` to a folder outside the repo, write the demo document over it, kill the process with `run-as ... kill`, take the shots (`animator_duration_scale` 0, System UI demo mode, `cmd uimode night no` then `yes`), crop 110px of status bar and 60px of navigation bar, then put the owner's file back, compare it byte for byte, restore the settings and reinstall the release build. Only capture while the app is in front and the phone is unlocked. The banner is `docs/assets/banner.py`.
- Test a place without moving: register a spot, then `adb emu geo fix <lng> <lat>` on an emulator, or a mock location app on the phone.
